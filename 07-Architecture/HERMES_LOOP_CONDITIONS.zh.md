## 1. 循环入口条件 (第 643 行)

```python
while (api_call_count < agent.max_iterations 
       and agent.iteration_budget.remaining > 0
      ) or agent._budget_grace_call:
```

三个条件控制循环入口：

| 条件 | 用途 |
|---|---|
| `api_call_count < agent.max_iterations` | 每回合 API 调用次数硬性上限（默认 10） |
| `agent.iteration_budget.remaining > 0` | 软预算系统（跨会话累计限制） |
| `agent._budget_grace_call` | 当预算恰好为 0 时额外允许一次"宽限"迭代，进入时消耗 |

**与我们实现的差异：** 我们的循环只检查 `apiCalls < maxIterations`。缺少 `IterationBudget`（跨会话累计）和 `_budget_grace_call`。

## 2. 所有 `continue` 触发条件（循环递归 / 继续迭代）

主 `while` 循环中有 12 个不同的 `continue` 站点导致 Agent 进行另一次 API 调用：

### 2A. API 前上下文压缩（第 1063 行）
```python
if _compressor.should_compress(request_pressure_tokens):
    messages = agent._compress_context(messages, ...)
    api_call_count -= 1  # 退还迭代次数
    continue
```
**作用：** 使用摘要 LLM 进行 Token 级别的上下文压缩。退还迭代次数，让压缩后的请求获得全新机会。  
**差异：** 我们的实现使用简单的消息数量裁剪，而非 Token 级别的压力估算或摘要 LLM 压缩。

### 2B. Nous 速率限制 → 故障转移（第 1133 行）
**作用：** 当 Nous Portal 速率限制器触发时，尝试激活备用提供商并重试。  
**差异：** 未实现（多提供商故障转移）。

### 2C. 内部重试循环：提供商特定重试（第 1489、1562、1718 行等）
`while retry_count < max_retries:` 内的多个 `continue` 站点：
- **瞬态 API 错误**与指数退避（相当于我们的 Step 2.4）
- **速率限制 (429)** 与自适应退避
- **凭据池轮转**（认证错误时）
- **备用提供商激活**（账单/内容策略错误时）
- **图像尺寸缩小**（提供商报告图像尺寸错误时）

**差异：** 我们实现了基本的重试与退避。缺少凭据轮转、故障转移链和图像缩小。

### 2D. 长度截断 → 续写重试（第 1949 行）
```python
if finish_reason == "length" and not _trunc_has_tool_calls:
    messages.append(continue_msg)  # "请继续..."
    break  # 跳出内部重试循环，继续外部循环
```
**作用：** 当 `finish_reason="length"` 时，追加 "请继续" 用户消息并再次循环（最多 4 次）。  
**差异：** **未实现** — 我们的循环完全不检查 `finish_reason`。

### 2E. 截断的工具调用 → 重试 API 调用（第 2000 行）
**作用：** 重试相同的 API 调用（不追加损坏的响应），并逐步增大 `max_tokens` 预算。  
**差异：** 未实现。

### 2F. 无效工具名称 → 自我纠正（第 4527 行）
**作用：** 当 LLM 幻觉出工具名称时，发送错误工具结果并再次循环以自我纠正。3 次重试后放弃。  
**实现状态：** ✅ **已实现** — 但缺少 3 次重试上限和模糊工具名修复。

### 2G. 无效 JSON 参数 → 重试 / 恢复（第 4590、4619 行）
**作用：** 两阶段恢复：先静默重试（最多 3 次），再注入错误工具结果。  
**实现状态：** ⚠️ **部分实现** — 我们立即注入错误结果（无静默重试阶段）。

### 2H. 工具执行 → 继续循环（第 4852 行）
**实现状态：** ✅ **已实现** — 这是主要的工具循环。

### 2I. 空响应 → 带推动重试（第 5008 行）
**作用：** 对真正空的响应最多重试 3 次。仍为空则尝试备用提供商。无备用则返回 `"(empty)"`。  
**实现状态：** ⚠️ **部分实现** — 我们注入推动用户消息；Hermes 静默重试。Hermes 还会在放弃前尝试备用提供商。

### 2J. 空响应 → 备用提供商（第 5040 行）
**差异：** 未实现（多提供商故障转移）。

### 2K. 验证停止门控 → 预验证推动（第 5266 行）
**作用：** 如果 Agent 在回合中修改了文件，拦截最终文本响应。注入 "请验证" 推动并再次循环，将原始响应保留为待定。  
**差异：** **未实现**。

### 2L. 意图确认续写（Codex 恢复）
**作用：** 模型说 "好的，我来做" 而没有进行工具调用时的恢复。  
**差异：** **未实现**。
